`lib/domain/ical-url.schema.ts` con `esquemaUrlIcal` y `hostsPermitidos`.

La validación se hace **parseando la URL** con el constructor `URL` y comprobando `protocol`, `hostname` y `pathname` por separado. **Nunca con una regex sobre la cadena entera**: `https://evil.com/?x=airbnb.com/calendar/ical/1.ics` la pasaría. Y el sufijo de host se compara como sufijo del `hostname` **precedido de punto o igual al host completo**, o `airbnb.com.evil.com` pasa.

**Concesión de testeabilidad, con candado:** cuando `NODE_ENV !== 'production'`, la allowlist admite además `127.0.0.1`. Es la única forma de que Playwright pruebe los siete estados: el fetch lo hace el **servidor**, así que `page.route()` no lo intercepta, y hay que levantarle un servidor HTTP local que sirva las fixtures. Documentarlo en el código como concesión deliberada, con el `NODE_ENV` como candado explícito.

`app/(admin)/apartamentos/[id]/calendario/_actions.ts` con `'use server'`, `import 'server-only'`, `export const maxDuration = 20`.

`validarFeed(propertyId, url)`:
1. `exigirAdmin()` — **antes de tocar nada**, y desde luego antes de cualquier cliente de servicio.
2. `esquemaUrlIcal.safeParse(url)` — si falla, estado 2, **sin ninguna petición de red**.
3. `fetch` con `signal: AbortSignal.timeout(10_000)`, `redirect: 'manual'`, `headers: { Accept: 'text/calendar, text/plain;q=0.9' }`, `cache: 'no-store'`.
   - **`redirect: 'manual'` es la segunda mitad de la defensa anti-SSRF.** La allowlist valida la URL que el usuario escribe, no a dónde termina el fetch: un 302 a `169.254.169.254` o a `localhost:54321` saltaría la validación de host. Con `redirect: 'manual'`, un 3xx se trata como feed inválido, que además es semánticamente correcto porque Airbnb sirve el `.ics` directo.
   - **`AbortSignal.timeout` y no `Promise.race` con `setTimeout`**: el primero aborta la conexión de verdad, el segundo deja el socket colgando.
4. Clasificar: 404/410, 403/401, 5xx, timeout o error de red → estado 7, con el copy por código de UI-SPEC §10.3. 3xx → feed inalcanzable.
5. Con 2xx, pasar el cuerpo a `previsualizarIcs(cuerpo, hoyIso)` del plan 02-03. Si devuelve `ok:false` → estado 6. Si `totalEventos === 0` → estado 5. Si no → estado 4.

**La URL nunca se escribe en un log ni en un mensaje de error.** Es una credencial: quien la tenga puede ver toda la ocupación del apartamento sin iniciar sesión. En el `last_error` de `calendar_feeds` va el status y el motivo, nunca la URL. Comentario explícito.

`guardarFeed(propertyId, url, resultado)`: **los dos clientes en una sola action, y el orden es el contrato.**
1. `exigirAdmin()` con el cliente del usuario.
2. `property_secrets.ical_url` con `createAdminClient()`. Medido: `42501 permission denied` incluso siendo admin con JWT de usuario, en SELECT y en UPSERT. No hay otra ruta.
3. `calendar_feeds` con el **cliente del usuario**: medido, el admin sí puede hacer upsert. Escribir solo las columnas de **salud** que ya existen para esto: `last_attempt_at`, `last_success_at`, `last_http_status`, `last_event_count`, `last_payload_hash`, `last_error`, `consecutive_failures`. Provider `'airbnb'`; `calendar_feeds_prop_provider_uniq` hace el upsert por `(property_id, provider)`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL escrita por el admin → fetch del servidor | El servidor hace una petición a una dirección que un usuario controla |
| Cuerpo del feed → escáner | Texto arbitrario traído de internet |
| `ical_url` → base, logs y DOM | Es una credencial: quien la tenga ve la ocupación completa sin autenticarse |
| Este plan → tablas de la Fase 3 | La costura que no se puede cruzar |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-72 | Server-Side Request Forgery | `fetch` de `validarFeed` | mitigate | Dos mitades: allowlist de host en Zod **antes** del fetch, parseando con `URL` y comparando `hostname` (no regex sobre la cadena), **y** `redirect: 'manual'`, porque la allowlist valida lo que el usuario escribe y no a dónde termina el fetch. Un 3xx se trata como feed inválido. Más timeout duro de 10 s con `AbortSignal.timeout` |
| T-02-73 | Information Disclosure | `ical_url` en un log o en `last_error` | mitigate | Regla dura escrita en el código: en `last_error` va el status y el motivo, nunca la URL. Test de integración que busca la cadena en la fila |
